# 控制需求描述边界测试方案

## 1. 测试目标

本轮只评价用户提交的控制需求描述，不评价大语言模型生成质量。目标是确认系统仅在需求具备可执行接口、确定行为、完整初值、冲突优先级和状态退出条件，且文本内部无直接矛盾时，才允许创建任务和产生模型费用。需求不足或冲突时，系统必须返回可操作的补充提示，不得让模型自行猜测或静默选择其中一种解释。

## 2. 判定层次

1. **文本与资源安全**：拒绝空白、控制/不可见格式字符、超长或高度重复文本、HTML/脚本片段、提示注入以及要求绕过验证的文本。
2. **接口完整性**：输入和输出均须具有 IEC 标识符与 `BOOL`、`INT` 或 `REAL` 类型；同一名称不得跨输入输出复用，也不得以不同类型重复声明。
3. **行为可判定性**：每个输出须有与已声明接口关联的确定规则；引用的条件变量必须已经声明；含糊阈值、时间和次数不得进入契约生成。
4. **状态语义完整性**：每个输出均须有确定初值；锁存、保持、定时、计数和边沿行为须分别给出退出条件、时间单位、计数阈值和边沿方向。
5. **内部一致性**：拒绝同一条件的相反赋值、冲突初值、恒定值与行为赋值冲突、锁存与下一扫描自动清除冲突，以及两节点或多节点优先级环。

## 3. 测试矩阵

| 类别 | 代表输入 | 预期结果 |
|---|---|---|
| 有效对照 | 组合逻辑、启停锁存、互锁、定时、计数、顺序控制，中英文及分节/紧凑写法 | 通过需求门禁 |
| 缺少信息 | 缺输入、输出、类型、输出规则、初值、优先级或锁存退出条件 | HTTP 422，指出具体缺失项 |
| 模糊描述 | “适当压力”“及时启动”“过一会儿”“达到一定次数” | HTTP 422，要求量化 |
| 接口异常 | 输入输出重名、同名不同类型、规则引用未声明变量、部分输出未初始化 | HTTP 422，定位变量 |
| 直接矛盾 | 同条件相反输出、相反初值、恒假同时要求置真、相互或成环优先级 | HTTP 422，列出冲突证据 |
| 时序异常 | 延时无数值/单位、计数无阈值、边沿无方向、保持状态无退出条件 | HTTP 422，要求补齐语义 |
| 对抗与资源 | 提示注入、要求跳过验证、脚本标签、不可见字符、重复文本、超长正文 | 在模型探测前拒绝 |
| API 异常 | 非法 JSON、错误字段类型、非法输出类型、幂等键冲突 | 4xx，不创建任务 |

## 4. 准入标准

- 所有有效对照均被接受，所有反例均在模型状态探测和任务创建之前被拒绝。
- 每个拒绝结果至少包含稳定错误代码、中文说明和可执行的修改建议。
- 反例请求前后活动任务数、后台提交数和模型探测次数均保持不变。
- 页面使用 `textContent` 展示输入和诊断，测试字符串不得被作为 HTML 执行。
- 完整自动化回归无新增失败；生产部署后重复执行 API 边界矩阵并保存脱敏结果。
