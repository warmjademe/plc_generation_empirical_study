# 控制需求描述边界测试报告

测试日期：2026-08-23
测试范围：控制需求输入、需求检查 API 与任务创建前门禁；未运行 PLC 代码生成，也未调用生产大语言模型。

## 结果

- 与生产一致的隔离环境及生产目录自动化回归均为 **208/208 通过**。
- 新增 **43 项**需求边界自动化断言，覆盖有效对照、缺失信息、模糊量词、接口异常、直接矛盾、时序异常、提示注入、不可见字符、重复/超长正文，以及“必须在模型探测前终止”的副作用断言。
- 生产 API 脱敏矩阵为 **21/21 通过**：5 个请求模式异常被 schema 拒绝，4 个完整正例被接受，12 个模糊/矛盾/对抗反例均返回 HTTP 422 且未创建任务。
- 生产 SQLite 任务总数在边界矩阵前后均为 **124**，证明反例没有进入任务队列；活动任务为 0。
- `plc-generation`、`plc-dvp-bridge` 与 `plc-generation-proxy` 三项服务均为 active，健康检查返回 `ok`，发布后服务日志无 warning 或 error。

## 已修正问题

原检查器能够发现接口缺失和少量直接冲突，但会错误放行冲突初值、恒定输出与行为冲突、保持后下一扫描清除、三节点优先级环、不同定时参数、未声明变量、部分输出未初始化、单个锁存输出无释放条件，以及提示注入和资源滥用文本。本次修正把这些情况加入确定性前置门禁，并为每个阻断项返回稳定检查 ID、中文说明、严重级别和证据摘要。

## 处理策略

系统按“文本安全 → 接口完整 → 行为可判定 → 状态语义 → 内部一致性”顺序检查需求。任一必需项不满足时，页面展示需要修改的项目，服务端再次强制拒绝任务；系统不会让模型猜测缺失值，也不会在相互矛盾的要求之间自行选择。只有全部检查通过后，才允许模型生成验证契约。

## 边界

该门禁针对可机械识别的显式缺失和矛盾，不能证明任意自然语言需求不存在隐含冲突。例如需要领域常识、物理设备约束或跨段复杂逻辑推理才能发现的问题，仍需由后续验证契约审计和用户确认处理。因此，产品声明应为“阻止已覆盖的模糊或矛盾输入进入生成”，而不是“证明所有自然语言需求一致”。
