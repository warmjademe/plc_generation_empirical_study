# PLC 生成服务生产就绪评审（2026-08-24）

## 1. 评审结论

当前版本可以继续用于受控的内部试运行，但暂不批准面向外部客户的无人值守生产发布。核心生成、契约、验证、下载、历史、取消、恢复和四节点调度路径已经具备自动化与真实工具链证据；严格发布门禁仍被四台 Windows 节点的长稳资格数量阻断。此外，正式对外服务前还应配置异机备份和主动告警，并完成一次维护窗口内的滚动重启演练。

本轮遵循无中断评审原则：完整测试在独立候选目录执行，生产环境仅执行只读状态、工具摘要、备份证据和 HTTPS 健康检查；没有创建模型任务、没有占用 Windows 验证节点，也没有重启在线服务。

## 2. 已确认的功能设计

- 用户可以提交正常或异常控制需求；确定性需求门禁会在产生模型费用前拒绝接口不完整、语义冲突、提示注入和当前 Oracle 无法表达的需求。
- DVP48ES300R 与 AS228T-A 分别支持 ST 和校准范围内的布尔 LD；可下载工程要求用户确认物理 I/O、有效电平和安全逻辑值。
- 生成闭环依次执行契约审计、MatIEC、PLCverif、OpenPLC 反馈测试、OpenPLC 确认测试以及目标型号 ISPSoft/COMMGR 门禁。任何必需验证器不确定时均失败关闭。
- 任务具有幂等创建、持久状态、租约续跑、取消、分页历史、筛选、归档、恢复、删除和受控工件下载能力。
- 四台 Windows worker 采用共享资源池和独占租约；单节点串行运行厂商桌面工具，多任务按健康状态和队列长度分配，超过四个并发厂商任务时进入等待队列。

## 3. 本轮修复的上线风险

1. 修复可下载工程契约确认区在长日志和移动视口中不可操作的问题，并加入真实 Firefox 的滚轮滚动、复选框和按钮可达性测试。
2. 增加跨进程登录失败限制；生产启动时拒绝默认/弱口令、会话密钥复用、SQLite 和公网直接监听。
3. 将任务重启保护从旧 SQLite 检查修正为读取生产 PostgreSQL 活动状态，避免错误判断“可以重启”。
4. 固定 MatIEC、PLCverif、nuXmv、CBMC、OpenPLC 和 PostgreSQL 的摘要，并在预检中失败关闭。
5. 增加数据库与证据联合备份、校验、保留策略和隔离恢复演练；备份校验使用随机容器临时文件，避免并发覆盖。
6. 调整发布脚本：先在候选目录测试，再进入切换；切换失败自动回滚；普通版本发布不同时重启四台 Windows 节点。
7. 增加单节点滚动重启脚本和带独占租约的每日双型号正反 canary，避免健康测试与用户任务共用一个模拟器会话。
8. 增加持久共享资源池锁，防止不同 systemd 私有临时目录导致多个进程同时选择同一 worker。
9. 为后台任务分发异常增加限频日志，避免数据库或租约故障被静默吞掉，也避免短周期重试造成日志风暴。

## 4. 验证证据

- Python 编译和 Shell 语法检查通过。
- 隔离候选目录自动化测试为 274 passed、1 skipped；跳过的 Node 辅助路径已由真实 Firefox 桌面视口和移动视口测试覆盖。
- DVP48ES300R/AS228T-A 研究适配层回归为 120 passed、1 skipped、7 subtests passed；首次隔离运行暴露的失败均由未装载共享研究夹具造成，补齐只读夹具后全量通过。
- Ruff 致命错误规则检查通过；依赖审计未发现已知漏洞。
- Bandit 报告的剩余项均经人工分类：固定字段集合构造的参数化 SQL、已强制 HTTPS 的模型 URL、本机固定健康 URL、固定参数的子进程调用及测试断言。未发现可由外部输入构造命令或 SQL 的路径。
- 工具摘要检查通过；Linux 正例通过全部门禁，注入错误的反例被语义门禁拒绝。
- 四个 Windows 节点当前均为 ready，两个型号能力完整，最近一次每日正反 canary 均通过。
- 已完成一次经哈希校验的数据库与证据备份，并成功恢复到临时数据库和临时证据目录；演练后已清理临时资源。
- 当前生产 PostgreSQL 中没有活动生成任务，外部 HTTPS 健康检查通过；内部试运行门禁通过。

## 5. 对外上线阻断项

1. **Windows 长稳资格未完成。** 严格门禁要求每台节点累计完成 100 个无模型正反厂商任务；当前四台节点均为 0/100。已有短并发和三周期长租约结果不能替代该资格。为不影响内部使用，应在维护时段分批执行，每次最多占用一台节点，并始终保留至少三台服务节点。
2. **备份仍在同一物理 VPS。** 当前备份和恢复机制有效，但主机级故障可能同时损坏源数据与备份。对外上线前应把加密备份复制到独立主机或对象存储，并对异机副本执行恢复演练。
3. **缺少独立主动告警通道。** systemd 会自动重启进程，页面也会展示状态，但服务、备份、canary、磁盘和 Windows 节点失败尚未接入独立告警。上线前应配置不含凭据和 Oracle 内容的告警，并验证通知闭环。
4. **尚未完成维护场景演练。** 需要在无活动任务时验证数据库重启、生成 worker 重启、Web 滚动更新和四节点逐台重启，确认租约续跑、排队、公网访问和下载均不受影响。

## 6. 非阻断改进项

- 为回收站、旧发布测试工件和审计环境增加独立清理周期与磁盘水位告警。
- 若未来从单租户扩展为多租户，需要增加用户隔离、角色权限、任务归属和审计日志；当前单一 `kemei` 用户假设不能直接外推。
- 公网入口建议增加 VPN、来源地址白名单或第二认证因素，降低单一账号暴露风险。
- 真实 PLC 下载前继续强制执行逐点 I/O、安全回路、急停和现场联调；ISPSoft/COMMGR 仿真不能替代硬件安全验收。

## 7. 放行条件

只有在严格 `release_gate.py` 返回 pass、异机恢复演练通过、主动告警测试通过、维护场景演练无数据丢失，并完成交付版本凭据扫描后，才应把状态从“内部试运行”改为“可对外生产发布”。
