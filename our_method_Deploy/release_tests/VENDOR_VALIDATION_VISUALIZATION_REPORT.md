# ISPSoft/COMMGR 动态验证可视化验收记录

日期：2026-08-23

## 用户界面

任务进入台达厂商验证后，进度对话框显示以下动态节点：

1. 任务入队与输入完整性检查；
2. 装载对应控制器的 ISPSoft 干净工程；
3. 绑定对应型号的 COMMGR 通信驱动；
4. 导入生成程序和测试 harness；
5. 使用 ISPSoft 编译工程；
6. 下载程序到仿真控制器；
7. 通过 COMMGR 执行仿真输入；
8. Oracle 判定与结果回传。

当前节点采用动态光效，已完成节点显示完成状态；涉及多组仿真输入时显示“仿真用例 i/n”。页面继续每两秒轮询任务进度，因此网络短暂中断后仍可恢复。

## 遥测与保密边界

Windows worker 为每个厂商验证任务写入追加式阶段事件。Linux 验证器核对内部任务标识后，将阶段名称、控制器型号、用例序号和总数复制到当前候选的公开进度文件。前端不接收用例标识、输入向量、预期输出、失败轨迹或密封 Oracle 内容。

## 验收结果

- DVP48ES300R 正确参考程序完成真实 ISPSoft/COMMGR 验证并通过。
- 实际观察到工程装载、通信绑定、程序导入、ISPSoft 编译、程序下载、COMMGR 执行、Oracle 判定和结果回传事件。
- 进度 API 能将当前阶段表示为结构化 `vendor_visualization`，并在真实任务中正确显示用例序号。
- 服务器端 165 项自动化测试通过；浏览器静态恢复测试 1 项通过，Node.js 任务恢复行为另在本机执行并通过。
- 生产服务、私网 Windows worker、DVP48ES300R 和 AS228T-A 验证环境保持在线。
