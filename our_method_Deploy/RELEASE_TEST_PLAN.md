# PLC 生成服务交付测试流程

本流程用于客户交付前的版本准入。测试对象包括 Web 权限、验证契约、模型调用、ST/LD 生成、MatIEC、PLCverif、OpenPLC、ISPSoft/COMMGR、任务进度、工件下载、并发和故障恢复。每个对客户开放的模型都应单独完成两个控制器与 ST/LD 的真实验收矩阵。

## 1. 准入原则

- 内部试运行期间，发布验证优先在独立候选目录执行；生产环境仅做只读健康检查。除非先确认没有活动任务并进入维护窗口，不得重启 Web、生成 worker、数据库或 Windows 验证节点。
- 每次发布固定代码版本、配置摘要、工具摘要和容器镜像 ID。
- 正例必须通过，注入错误的反例必须被对应门禁拒绝；只测正例不能证明验证器没有假阳性。
- 模型空响应、输出截断、HTTP 429/5xx、超时和流中断属于可恢复调用错误，在同一候选槽内最多调用三次，不消耗新的候选机会。
- 缺少凭据、未知模型、服务端模型身份不匹配、非法目标型号等配置错误必须立即失败。
- 任一必需验证器返回不确定结果时，不得标记程序成功；台达任务必须以 ISPSoft/COMMGR 最终门禁通过为成功条件。
- 测试报告不得包含模型密钥、登录密码、隐藏 Oracle 详情或服务器凭据。

## 2. 自动化测试层次

1. **静态与配置检查**：Python 编译、JSON 解析、模型和厂商目录、默认选项、LD 支持范围、部署文件权限及凭据扫描；生产目录必须只包含台达，且不得出现 DeepSeek V4 Flash 或 Kimi K3。
2. **单元测试**：契约规范化与矛盾审计、ST/LD 响应提取、Ladder IR 到 ST/SVG/FBU 的确定性转换、模型错误分类、进度事件、会话签名、PostgreSQL/SQLite 原子状态迁移、任务租约、取消和模型并发/限速/熔断。OpenPLC 执行器必须直接复用契约模块的语义审计版本；固定正反例夹具也必须与该版本一致，防止组件版本漂移使有效 Oracle 被误拒绝。
3. **故障注入测试**：契约和候选阶段分别注入空响应、`finish_reason=length`、503、429、DNS/连接失败、超时、错误模型身份、验证器失败/不确定/超时和重复候选。断言重试次数、候选计数、终局状态及用户日志；模型已离线时必须在创建任务前失败，运行中断网必须终止为基础设施错误而非程序失败。所选模型的提交前探测最长 12 秒且不做传输重试，正式生成调用保留自身的有界重试。
4. **API 生命周期测试**：未登录访问拒绝、登录/退出、目录读取、任务创建、五秒自动确认和人工确认竞争、任务轮询、终局状态、ST/LD 工件授权下载和非法工件拒绝。
5. **Linux 验证链测试**：已知正确 ST 必须依次通过 MatIEC、PLCverif、OpenPLC feedback 和 OpenPLC confirmation；已知错误 ST 必须被 PLCverif 和两组 OpenPLC 拒绝。
6. **厂商链测试**：DVP48ES300R 的 ST 与布尔 LD 正例必须通过 ISPSoft 编译、COMMGR DVP-ES3 连接和全部 Oracle；语法变异及行为变异必须分别在编译或 Oracle 阶段失败。AS228T-A 使用相同原则单独验收，不得用 DVP 结果代替。
7. **并发与恢复测试**：至少两个浏览器会话并行创建、轮询和下载时不得串任务；活动任务容量必须原子执行，超限返回 429；模型实际生成调用必须遵守提供方级并发、每分钟配额和熔断；每个 Windows 节点只能串行消费，多个节点应并行处理不同 job ID；页面强制刷新后必须恢复原任务；服务重启后，任务应在租约过期后从既有账本继续且不得重复已完成候选；取消后不得发出新的模型请求或厂商任务。
8. **真实模型验收**：分别选择生产目录中的 DeepSeek V4 Pro 与 Claude Sonnet 5，从受保护的 Web API 对 DVP48ES300R 与 AS228T-A 提交 ST 和布尔 LD 任务，并覆盖启停联锁、锁存复位、互斥控制和顺序状态等不同需求。每个任务完整经过契约、反馈迭代和对应厂商门禁。记录任务 ID、终局状态、候选数、重试日志、验证门禁和耗时，不保存凭据或隐藏 Oracle。
9. **需求输入矩阵**：使用中文分节、中文紧凑描述、英文自然语言、表格化文本和 JSON 风格文本作为有效输入，并覆盖启停、互锁、锁存复位、顺序状态、计数和模拟量规则；使用缺少接口变量名/类型、未覆盖全部输出、模糊初值、模糊优先级、锁存无退出条件、输入输出重名以及直接矛盾的描述作为反例。有效输入应进入契约阶段，反例应返回具体缺失项且不得创建任务。
10. **需求追踪审计**：每条冻结需求必须映射到形式性质或状态规则、反馈测试和确认测试；安全关键需求还必须映射到形式性质。删除任一映射后，契约必须在候选生成前失败关闭且不得自动确认。
11. **优先级一致性审计**：对契约中明确声明的高到低输入优先级，每一对相邻层级的输入都必须在反馈测试和密封测试中分别同时置为 TRUE；缺少任一组合即视为覆盖不足。对这些步骤再执行反事实检查：抑制低优先级事件前后，受状态规则管理的输出不得变化，否则说明低优先级事件越过了高优先级事件，契约必须在候选生成前被拒绝。
12. **幂等提交测试**：浏览器为一次提交生成并暂存 `Idempotency-Key`。模拟服务器已创建任务但客户端响应超时后，以同一键并发重试；所有响应必须返回同一 job ID，后台契约任务只允许启动一次。相同键用于不同请求必须返回 409。
13. **Windows 长稳测试**：每个新节点先连续执行至少 100 个无模型正反向厂商 canary，两个型号均要求正确程序通过、错误程序被拒绝、job/worker/hash 身份一致且无跨任务污染。准入后每日运行同一正反向 canary；任一极性不符、心跳超时或证据身份错误立即将节点标记为 quarantined。worker 每处理 25 个任务自动回收 ISPSoft、COMMGR 和模拟器会话；运维在预定窗口对虚拟机做滚动重启，并始终保留其他已准入节点服务。

## 3. 发布命令与判定

基础自动化测试：

```bash
PYTHONPATH=src PLC_PROJECT_ROOT="$PWD" pytest -q
python -m compileall -q src scripts
python scripts/preflight.py
```

生产环境还需核对：

```bash
python scripts/check_active_jobs.py
systemctl is-active plc-generation.service plc-generation-worker.service \
  plc-generation-postgres.service plc-generation-proxy.service \
  plc-dvp-bridge@01.service plc-dvp-bridge@02.service \
  plc-dvp-bridge@03.service plc-dvp-bridge@04.service
curl -fsS http://127.0.0.1:18081/health
python scripts/release_gate.py --minimum-qualification-jobs 0
python scripts/release_gate.py
```

第一条门禁用于确认内部试运行服务仍可用，第二条严格门禁还要求每个 Windows 节点完成规定数量的长稳资格任务。对外发布必须同时满足以下条件：自动化测试零失败；正反向 Linux 预检通过；生产模型实际推理在线；两型号正反向厂商测试通过；真实 ST 与 LD 任务没有假成功；浏览器日志可显示模型重试和每个验证器的开始、结束与错误；服务重启和并发测试没有遗留运行任务；严格发布门禁通过。任何一项不满足即停止上线，并保留失败证据用于修正。

## 4. 回归范围

模型客户端、契约、编排器、验证器、任务状态、进度页面、控制器目录、Windows worker 或部署配置任一部分发生变化后，都必须重新运行全部自动化测试与对应工具链测试。仅修改样式时可免除真实模型生成，但仍需运行 API、权限和浏览器交互测试。
